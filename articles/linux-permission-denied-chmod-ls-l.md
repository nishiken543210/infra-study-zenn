自分で書いたスクリプトを動かそうとして`Permission denied`と出ると、何か壊してしまったのかと不安になります。自分も入社2年目のころ、自作のスクリプトで権限につまずき、`chmod`や`chown`で直した覚えがあります。そこで改めて、自分のスクリプトにわざと`Permission denied`を出させて、`ls -l`を読み直してみました。これは壊れた印ではなく「誰が何をしてよいか」の知らせで、答えは`ls -l`の左端10文字にあり、読めば`chmod`で必要な分だけ足して直せます。

この記事で分かることは、次の3つです。

- `ls -l`の左端10文字から、誰に何の権限があるか読めます
- `chmod`の数字と記号を使い分け、必要な権限だけ直せます
- 所有者とグループを見て、ファイルを読める理由を説明できます

## 最初に「自分が誰か」を見る

Linuxの権限は、同じファイルでも操作する人によって結果が変わるため、先に今のアカウントと所属グループを見ました。

```bash
id
```

```text
uid=1003(student) gid=1003(student) groups=1003(student),4(adm)
```

`uid`はユーザーの番号、`gid`は基本となるグループの番号です。このアカウントは`student`で、`student`と`adm`の2グループに入っています。

グループ名だけなら、`groups`でも確かめられます。

```bash
groups
```

```text
student adm
```

グループへ追加された直後は今のシェルに所属情報が出ない場合があるため、一度ログアウトし、ログインし直してから`groups`を見ます。

## 左端10文字を1文字と3文字ずつに分ける

あらかじめ作っておいた`~/bin/hello`は、名前とホスト名を表示する70バイトのスクリプトです。最初の権限を`ls -l`で見ました。

```bash
ls -l ~/bin/hello
```

```text
-rwxr-xr-x 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

左端の`-rwxr-xr-x`は、次の4区画に分かれます。

```text
- | rwx | r-x | r-x
種別  所有者  グループ  その他
```

先頭の`-`は通常ファイルです。続く9文字は3文字ずつ、所有者の`user`、所有グループの`group`、それ以外の`others`を表します。各区画に出る文字は、`r`が読む、`w`が書く、`x`が実行する権限です。権限が無い場所には、文字の代わりに`-`が出ます。

このファイルの3列目と4列目は、どちらも`student`です。3列目は所有者、4列目は所有グループなので、今の自分は最初の`rwx`を使えます。

持ち主そのものが違う場合に使うのが`chown`です。ただし、所有者を変えるには通常、管理者の権限が要ります。今回は実測した出力がないため、`chown`の操作までは進めません。

## 755は3組の足し算だった

`r`、`w`、`x`には、それぞれ4、2、1という数字が割り当てられています。3文字の区画ごとに、ある権限の数字を足します。

| 表記 | 足し算 | できること |
|---|---:|---|
| `rwx` | 4+2+1=7 | 読む・書く・実行する |
| `r-x` | 4+0+1=5 | 読む・実行する |
| `rw-` | 4+2+0=6 | 読む・書く |
| `r--` | 4+0+0=4 | 読むだけ |

つまり`-rwxr-xr-x`は、所有者が7、グループが5、その他が5なので755です。

よく見る形も、同じ読み方で分けられます。

| 数字 | 10文字 | 読み方 |
|---:|---|---|
| 755 | `-rwxr-xr-x` | 所有者は全部、ほかは読み取りと実行 |
| 644 | `-rw-r--r--` | 所有者は読み書き、ほかは読み取りだけ |
| 600 | `-rw-------` | 所有者だけが読み書きできる |
| 744 | `-rwxr--r--` | 所有者だけ実行でき、ほかは読み取りだけ |

600は、SSHの秘密鍵でよく使われる形です。誰に何を許すかが違うので、どのファイルにも同じ数字を入れればよいわけではありません。

## わざと実行できなくしてみる

ここからの手順は、[本物のサーバで無料で試せます](https://infra-study.org/part1-chapter07)。章の中に実機の操作を再生できる画面があり、先に動きを見てから同じコマンドを打てます。

自分のスクリプトを644へ変え、実行を表す`x`を3区画すべてから外しました。

```bash
chmod 644 ~/bin/hello
```

`ls -l`で、指定した形になったかを見ます。

```bash
ls -l ~/bin/hello
```

```text
-rw-r--r-- 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

所有者は`student`で、今操作している本人です。それでも、所有者の3文字が`rw-`なので、ファイルとして実行する権限はありません。

```bash
~/bin/hello
```

```text
bash: /home/student/bin/hello: Permission denied
```

*「自分のファイルなのに、自分でも動かせないのか」*

ファイルの`x`が無ければ、所有者本人でも実行できません。ただ、表示されたのは中身が壊れたという知らせではなく、今の権限ではその操作を許可しないという結果です。実際、サイズは70バイト、更新日時は`Jul 26 17:41`のままです。755から644へ変わったのは左端の権限で、ファイルの中身ではありません。

## 必要な人へ、必要な権限だけ戻す

数字の`chmod 644`は、所有者・グループ・その他の3区画をまとめて指定します。一部分だけ変えたいときは、記号で書くほうが意図をそのまま残せます。

今回は所有者を表す`u`へ、実行の`x`だけを`+`で足しました。

```bash
chmod u+x ~/bin/hello
```

```bash
ls -l ~/bin/hello
```

```text
-rwxr--r-- 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

変わったのは、所有者の区画にある3文字目だけです。`-rwxr--r--`は数字なら744で、グループとその他には実行権限を足していません。

もう一度スクリプトを動かします。

```bash
~/bin/hello
```

```text
こんにちは、student さん！ (from <ホスト名>)
```

中身を直さなくても、所有者に`x`を戻すと同じスクリプトが動きました。`Permission denied`の前後で見る場所は、エラーだけではなく、誰がどの区画を使うかです。

## 600でふさぎ、755へ戻す

今度は600を指定し、所有者以外の権限をすべて外しました。

```bash
chmod 600 ~/bin/hello
```

```bash
ls -l ~/bin/hello
```

```text
-rw------- 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

600では所有者だけが読み書きでき、所有者にも実行の`x`はありません。最後に、最初と同じ755へ戻しました。

```bash
chmod 755 ~/bin/hello
```

```bash
ls -l ~/bin/hello
```

```text
-rwxr-xr-x 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

数字方式は3区画を一度に決め、記号方式は今ある権限の一部だけを変えます。結果の10文字を`ls -l`で読み返すところまでが、ひとまとまりの作業です。

## 権限を変えても中身の更新日は変わらない

権限はファイルの本文ではなく、そのファイルを管理するinodeに記録されています。inode番号を表示する`ls -li`では、行の先頭に`396581`と出ました。

```bash
ls -li ~/bin/hello
```

```text
396581 -rwxr-xr-x 1 student student 70 Jul 26 17:41 /home/student/bin/hello
```

`stat`を使うと、同じinode番号と、権限を数字・10文字の両方で見られます。

```bash
stat ~/bin/hello
```

```text
  File: /home/student/bin/hello
  Size: 70         Blocks: 8          IO Block: 4096   regular file
Device: 252,0      Inode: 396581      Links: 1
Access: (0755/-rwxr-xr-x)  Uid: ( 1003/ student)   Gid: ( 1003/ student)
Access: 2026-10-26 11:47:49.764000000 +0900
Modify: 2026-07-26 17:41:49.549000000 +0900
Change: 2026-10-26 11:47:50.460000000 +0900
 Birth: 2026-07-26 17:41:49.549000000 +0900
```

`ls -li`の`396581`と、`stat`の`Inode: 396581`は同じです。`Access: (0755/-rwxr-xr-x)`にも、ここまで読んだ2種類の表記が並んでいます。

`Modify`はファイルの中身が変わった時刻で、7月26日のままでした。一方、権限などinodeの情報が変わると`Change`が更新され、今回は10月26日になっています。

*「chmodで変わったのは、中身ではなくこちらなのか」*

この違いを知っていると、実行できなくなった前後で`Modify`が変わっていなくても不思議ではありません。見るべきなのは、権限の10文字と`Change`です。

## グループに入っているから読めるファイル

所有者ではなく、所属グループの3文字が使われる例も見ました。Ubuntuの認証ログ`/var/log/auth.log`は、次の所有者と権限でした。

```bash
ls -l /var/log/auth.log
```

```text
-rw-r----- 1 syslog adm 20573 Oct 26 11:47 /var/log/auth.log
```

所有者は`syslog`、所有グループは`adm`です。権限`-rw-r-----`を分けると、所有者は読み書き、`adm`グループは読み取りだけ、その他は何もできません。最初の`groups`には`student adm`と出ていました。`student`は所有者ではありませんが、`adm`の一員なので、中央の`r--`を使って読めます。

```bash
head -3 /var/log/auth.log
```

ここでは、表示の先頭の1行だけを載せます。

```text
2026-10-26T09:55:01.753493+09:00 <ホスト名> CRON[1292]: pam_unix(cron:session): session opened for user root(uid=0) by root(uid=0)
```

グループの登録側も見ました。実際の行には、この後ろにほかのアカウントも続きますが、ここでは伏せています。

```bash
grep '^adm:' /etc/group
```

```text
adm:x:4:syslog,student
```

ここでは、`adm`に入っていないアカウントで拒否される出力までは採っていません。ただ、左端10文字を読めば、その他の区画は`---`で何も許されていないと分かります。

## この記事で扱わないこと

ここで扱ったのは、通常ファイルの`ls -l`を読み、自分が所有するファイルの権限を`chmod`で変えるところまでです。ディレクトリでは`x`が「中に入れる」、つまり`cd`できる権限を表しますが、詳しい組み合わせは含めません。

管理者権限が要るファイルを`sudo`で押し切ること、ACLによる追加の権限、所有者を変える`chown`の実演も扱いません。対象と理由を確かめずに`chmod 777`ですべての人へ全権限を渡す直し方も、ここでは選びません。

## まとめ：拒否されたら、左端10文字へ戻る

`Permission denied`は壊れた印ではなく「誰が何をしてよいか」の知らせで、`ls -l`の左端10文字を読めば、必要な権限だけ`chmod`で直せます。
